# 招募发现与申请人侧交接

## 分工与目标

完成“发现招募 → 收藏 → 提交申请 → 查看结果或撤回”的流程。
继续保留已有项目、任务和招募发布管理页面，不顺带重构。

本文基于当前 `main` 和本周任务整理。接口字段以[最新 API 规范](../../docs/recruitment-api-spec.md)为准；
目前为待实施任务，不代表已经完成。真实接口已存在的部分不使用 Mock 或模拟成功回退。

## 需要完成

### 1. 大厅增强

- 新增多选技能标签、最少剩余名额，以及 `POPULAR` 排序。
- 保留关键词、分类、课程、教师、公开状态筛选和分页。
- `tagIds` 以逗号分隔字符串提交，匹配任一标签；`minRemainingSlots` 是大于等于 0 的整数，0 不能误当作未填写。
- 新增条件和页码继续保存到 URL；搜索、排序和筛选改变后回到第一页。
- 所有筛选排序由后端完成；保持请求取消/旧响应隔离、加载、空结果和错误重试。
- 默认状态为 `RECRUITING`，不发送 `ALL`。

### 2. 收藏与我的收藏

- 卡片、详情提供收藏/取消收藏，新增“我的收藏”页。
- 收藏状态集中管理，并同步到卡片、详情和收藏页；读取服务端 `favorited` 字段。
- 同一招募操作中禁用按钮；成功后更新，失败保留原状态并提示。
- 未登录点击收藏，跳转登录并携带原页面地址；登录后返回，不自动代替用户执行收藏。
- 用户退出或切换账号时清理收藏缓存；不得把上一个账号状态复用给新用户。

### 3. 详情申请与我的申请

- 提供申请表单：`introduction`、`skillsDescription`、`availableTime`。
- 前两项各最多 1000 字符，可投入时间最多 255 字符，均可选，不自行增加后端未规定的必填规则。
- 展示本人对当前招募的申请状态，待处理时支持确认后撤回。
- 通过本人申请列表匹配当前招募，按最新申请展示状态，保留历史；不调用仅负责人可访问的申请列表。
- 区分已截止、满员、已成队、已关闭、负责人、正式成员及重复待处理申请等情况。
- 负责人和已加入成员不显示申请入口。成员身份使用正式成员列表判断，不能仅凭历史 ACCEPTED 申请认定仍在队。
- 申请状态/成员查询失败时显示重试，不把“查询失败”当成“可以申请”。
- 新增“我的申请”页：招募标题、申请时间、状态、处理时间/拒绝原因、待处理撤回、进入招募详情。
- 撤回或被拒后允许重新申请；遇到 `409` 提示具体冲突并刷新申请、招募及成员状态，不模拟成功。

## 接口

下列为完整后端路径，使用公共 Axios 时省略 `/api`。

| 接口 | 用途与返回 |
| --- | --- |
| `GET /api/recruitments` | 服务端筛选分页，新增 `tagIds/minRemainingSlots/POPULAR` |
| `GET /api/tags` | 可选技能标签 |
| `POST /api/recruitments/{id}/favorite` | 收藏；统一空数据响应 |
| `DELETE /api/recruitments/{id}/favorite` | 取消收藏；统一空数据响应 |
| `GET /api/recruitments/favorites` | 收藏时间倒序的招募数组，不是分页对象 |
| `POST /api/recruitments/{id}/applications` | 提交申请，成功 HTTP 201 |
| `GET /api/applications/me` | 本人历史申请数组 |
| `PATCH /api/applications/{id}/withdraw` | 撤回待处理申请，返回更新后的申请对象 |
| `GET /api/recruitments/{id}/members` | 正式成员数组，使用对方提供的封装与组件 |

申请状态统一为 `PENDING/ACCEPTED/REJECTED/WITHDRAWN/EXPIRED`。
同一用户最多一条待处理申请，待处理申请不占正式名额。服务端状态和权限判断为最终依据。

## 缺失字段的临时处理

- 当前申请对象没有招募负责人字段。“我的申请”先不展示负责人，不为每一行追加详情查询。
- 不伪造负责人，不写“负责人未填写”；这属于接口尚未返回信息。
- 待后端补充后再扩展类型和展示，不自行把约定字段作为已存在的响应使用。

## 与其他模块的对接

- 本模块维护详情外壳，拆出申请区域组件；成员列表由审核模块提供后嵌入。
- 建议新增 `/my-favorites` 和 `/my-applications`，均设置 `meta.requiresAuth`；和公共负责人协调导航与路由。
- 本模块维护 `src/api/applications.ts` 及 `src/types/application.ts`，集中提供提交、本人查询、撤回以及审核接口；审核模块复用并协调修改。
- 收藏可独立放 `src/api/favorites.ts` 与对应 Pinia Store，避免详情和卡片各维护一套状态。
- “我的申请”接受可选 `applicationId` query，便于通知定位；无法找到时显示友好提示，不隐藏其他历史记录。
- 负责人审核通知暂由公共模块跳“我的招募”，申请人通知跳“我的申请”；不要依赖尚不存在的单条申请详情接口。
- 申请或撤回成功后通知公共模块刷新未读数，不由客户端创建通知。

## 交付验收

- URL 可恢复新旧筛选条件及页码，返回大厅保留条件，热门排序由服务端完成。
- 游客点击收藏能登录返回；三个入口的收藏状态一致，失败不改变状态，换账号无串数据。
- 完成申请、查看状态、撤回、再次申请；重复提交、无名额、截止等场景反馈正确。
- 成员查询失败有重试；正式成员和负责人没有申请入口。
- 每个页面具备加载、空数据、失败、重试及无权限状态；处理 `400/401/403/404/409/500`。
- 运行 `npm run lint:check`、`npm run format:check`、`npm run build`，配合真实后端完成两账号验收。
- 交付时说明真实接口接入范围、仍预留的字段、测试结果；不修改通知或公共鉴权实现。
