## 已注册页面

| 路径 | 行为 |
| --- | --- |
| `/my-teams` | 从本人有效 TEAM 会话出发展示已成队队伍、正式角色、人数与群入口；保留只读队伍。 |
| `/my-member-exits` | 本人退出历史、原因、状态、处理时间、拒绝原因及交接提示；不提供负责人审批动作。 |
| `/my-leader-transfers` | 本人发起/收到的转交，指定继任者可接受/拒绝待确认记录；支持 `transferId` 定位。 |

全部通过 `createTeamRoutes` 注册并受登录保护。现有侧栏按已注册路由显示入口。

## 详情与权限

- 联系负责人调用 `createPrivateConversation(ownerId)`，复用统一聊天页并传公开招募来源；没有自动发送消息。游客登录返回，当前负责人不显示联系自己，屏蔽/无权限/不存在及网络错误单独提示。
- 群入口通过 `getTeamConversation` 获取并在进入前再验证，使用返回的会话 ID。群 403/404 只影响群入口，不影响公开招募详情。无聊天路由时显示待接入，不创建空页面。
- 普通成员可填写最多 255 字的可选原因，确认后提交退出申请。待审批时仍保留成员资格和群入口；负责人只显示转交引导。
- 负责人发起转交的管理页面目前尚未注册，因此指引文案显示“负责人发起转交入口待管理模块接入”。注册 `teamManagement` 后会自动显示对应跳转，不需要更改本模块。
- 转交接受/拒绝均二次确认；展示服务端 handoverHint 和 `exitAfterTransfer` 的去留含义。接受后重新查询负责人、正式成员、群权限，并复用通知刷新；不能直接修改本地角色或人数。
- 详情新增“刷新详情与成员”，可主动同步其他账号完成的审批/转交。业务页不新增后台轮询；重新进入、手动刷新及公共失效信号均重查实际权限。
- 我的队伍对单条错误和列表错误分别展示。查询最多三个并发；身份撤销后重查有效会话并撤下失效群入口，失败不会显示成空列表。

## 共享与异常处理

复用 `api/team-management.ts`、`api/conversations.ts`、`api/members.ts` 和招募查询；没有新增重复业务接口。
`useTeamRead` 在账号、查询条件变化或卸载时取消旧请求；`useTeamAction` 在写入前捕获 session，成功调用 `afterTeamMutation`，403/404/409 失效重查且不重发写请求。

`teamErrorStatus` 兼容旧招募/成员封装的数字业务码，保留 Axios 的状态处理。公共 Token、401、通知算法及聊天发送/轮询实现未修改。
成功后刷新失败分别显示成功结果和刷新错误；用户可重试读取，无需重复接受/提交。

## 测试环境与复跑

后端使用独立 H2 内存库，未访问现有业务数据库。原 H2 schema 缺少 `member_exit_request`、`leader_transfer` 以及退出通知枚举，本次按正式数据库字段/约束补齐测试结构，未改后端业务代码。
本机 Node 22.22.2、Java 21（项目编译目标 17）；正式环境仍按后端说明使用 Java 17。

浏览器脚本会在目标后端创建测试账号和队伍，**只指向独立测试库**。
默认 `API_BASE=http://127.0.0.1:18080/api`、`FRONTEND_URL=http://127.0.0.1:5173`，前端通过 `API_PROXY_TARGET=http://127.0.0.1:18080` 代理。
可配置 `PLAYWRIGHT_MODULE`（已有模块入口）、`CHROMIUM_EXECUTABLE`、`OUTPUT_DIR`。截图默认在系统临时目录 `teamflow-member-side-e2e/`；无账号 Token 写入仓库。

```bash
node scripts/check-team-member-side.mjs
node scripts/check-team-member-side-e2e.mjs
```
