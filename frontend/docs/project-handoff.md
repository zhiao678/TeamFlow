# 项目模块交接

## 实施顺序与成果

1. 项目 API 封装：新增 src/api/projects.ts，保留公共 Axios 行为，检查业务码。
2. 项目列表：真实接口、详情链接、加载、空列表、失败重试。
3. 项目详情：概览、成员和任务子路由；默认跳转概览；处理无效编号与不存在的项目。
4. 成员展示：展示详情接口提供的创建者，明确完整成员列表暂不可用，不伪造成员数据。
5. 任务交接：预留任务子页面，不实现任务列表、创建或状态修改。
6. 验证：执行 lint:check、format:check、build，并检查浏览器正常及异常流程。

## 页面与接口

| 路径 | 路由名称 | 内容 |
| --- | --- | --- |
| /projects | — | GET /api/projects |
| /projects/:projectId | — | 详情外壳，GET /api/projects/{id}，默认跳转概览 |
| /projects/:projectId/overview | project-overview | 项目基本信息 |
| /projects/:projectId/members | project-members | 创建者信息与成员功能说明 |
| /projects/:projectId/tasks | project-tasks | 任务模块待接入页面 |

任务负责人将 project-tasks 路由的组件替换为正式任务页面即可。
从 useRoute().params.projectId 获取编号；详情外壳同时向子页面传入 project 属性。
父页面在项目切换时取消旧请求并清空旧数据；子页面以项目 ID 为 key，切换项目会重新创建。
任务页不需要再次绘制公共布局或项目页签。

## 数据边界

- 列表、概览及创建者来自真实项目接口，不回退为模拟数据。
- 成员列表接口仍需后端提供，当前不支持邀请、删除成员或编辑角色。
- 任务页只是入口，正式任务功能由任务负责人接入。
- 工作台、我的任务、消息及顶部用户仍沿用原有模拟数据。
- 不包含创建、编辑、删除项目，这些不在本次项目模块分工中。

## 启动与验收

在 frontend 目录执行 npm ci、npm run dev；启动后访问 /projects。
后端默认由 Vite 代理到 http://127.0.0.1:8080，可用 API_PROXY_TARGET 调整。
需按 backend/README.md 启动后端，或使用仓库已有演示启动方案。
部署 History 路由时应将前端页面请求回退到 index.html。

- 点击项目卡片，检查详情 ID 和内容对应。
- 在概览、成员、任务之间切换，检查页签和侧栏高亮。
- 直接访问及刷新详情和子页面。
- 检查不存在项目、无效编号、列表为空、接口失败和重试。
- 窄屏检查文字换行、页签及内容区域。
- 成员完整列表及正式任务交互需待相关模块接入后另行验收。
