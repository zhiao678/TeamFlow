# 招募发布与管理交接

`/recruitments/new`、`/recruitments/:id/edit`、`/my-recruitments` 三个页面已完成，纳入现有公共布局，侧栏新增「我的招募」，招募详情对负责人显示「编辑这条招募」。

## 已完成

- 共用表单：分类、标题、课程、教师、组队目的、详细说明、要求、人数上限、截止时间、技能标签；校验规则与后端 `CreateRecruitmentRequest` 对齐（标题 150、目的 200、课程/教师各 100、总人数 ≥ 2）。
- 新建：保存草稿、直接发布；成功后进入「我的招募」。
- 编辑：回填详情、保存修改、把草稿发布、关闭招募（带原因与二次确认）；TEAMED/CLOSED 只读并说明原因。
- 我的招募：状态筛选（URL query 保存）、分页无（本周后端未提供）、发布草稿、关闭、编辑、查看详情。
- 未登录跳登录、非负责人、404、409 均有明确文案；提交中禁用按钮，失败保留输入。

## 数据边界与临时方案（都已在界面上标注）

- `GET /api/recruitments/mine` 尚未实现：先用 `GET /api/recruitments` 按 `ownerId` 过滤，页面顶部说明这是临时来源。
- `GET /api/categories`、`GET /api/tags` 尚未实现：使用与 `database/recruitment-init.sql` 种子数据一致的临时选项，页面顶部说明待替换。
- `DELETE /api/recruitments/{id}` 尚未实现：删除草稿按钮禁用并注明「接口未提供」，没有用关闭代替删除。
- 详情只返回标签名称，编辑时按名称匹配选项得到 `tagIds`；存在匹配不上的标签时，未改动标签的保存不会提交 `tagIds`，避免覆盖原有标签。接口提供 `tagIds` 后可删除这段逻辑。
- `PATCH` 以 `null` 表示「不修改」，所以截止时间无法清空，表单里如实提示；空文本字段提交空字符串，保证能清空说明和要求。

## 本次验证

- `npm run lint:check`、`npm run format:check`、`npm run build`（含类型检查）均通过。
- 用 `recruitment-test` 的 H2 库起了真实后端，Chrome 无头浏览器走了一遍：登录 → 我的招募 → 新建（空表单报 3 条校验错误、填完后报错自动消失）→ 保存草稿 → 列表 +1 → 打开编辑回填正确 → 列表发布草稿 → 关闭招募（二次确认）→ 状态筛选计数正确。
- 浏览器里观察到 `/api/recruitments/mine` 返回的是 400 而不是 404：请求被 `GET /recruitments/{id}` 接住，`mine` 解析不成数字 id。代码已把 400 一并视为“接口未提供”，否则会误报错误。
- 真实接口补齐后，仍需按下面清单回归一遍。

## 待回归清单

1. 存草稿 → 刷新 → 草稿仍在，且游客/他人看不到。
2. 直接发布 → 大厅可见、详情可打开。
3. 编辑保存 → 刷新后字段、标签、截止时间一致。
4. 草稿发布 → 状态变为招募中；重复点击只成功一次。
5. 关闭 → 状态变为已关闭，列表不再提供编辑与关闭入口。
6. 非负责人直接访问 `/recruitments/{id}/edit` → 无权提示，服务端 403 不被吞掉。
7. 未登录访问三个路由 → 跳转登录并带回跳地址。
8. `/recruitments/new` 不会被 `/recruitments/:id` 当成 ID（路由已把静态段放在动态段之前）。
