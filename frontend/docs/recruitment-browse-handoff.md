# 招募浏览交接

游客可从侧栏进入 `/recruitments`，点击标题查看 `/recruitments/:id`。默认显示 RECRUITING；搜索匹配标题、组队目的／活动、课程和教师，可叠加分类、课程、教师及公开状态筛选。点击搜索应用条件并回到第一页，刷新或从详情返回保留查询和页码。每页 20 条；即将截止按未来的北京时间升序，已过期或无截止日期的记录排在其后。

## 数据边界

- 复用公共请求实例和认证处理。当前 GET 列表返回数组，大厅先排除草稿，再在浏览器筛选、排序、分页；没有模拟数据回退。分类来自公开结果，因此不等于完整分类目录。
- 服务端分页完成后须改用查询参数和分页响应；不可仅在服务端返回的一页中筛选。技能／缺额筛选和热门排序属于总规划，不在本周浏览任务内。
- 管理模块可复用 `src/types/recruitment.ts` 的 Recruitment、RecruitmentStatus、statusLabels、displayStatus、timestamp 和 `src/api/recruitment-query.ts` 的 getRecruitment(id, signal?)。tags 当前是名称而非表单所需的 ID；回填仍需后端约定。
- 详情展示负责人而非完整成员名单。已截止、满员是派生提示，不是后端状态；申请、私聊、收藏未开放。草稿详情依服务端鉴权，未授权可能得到 404 而非 403，以实际响应显示。

## 本次验证

- lint:check、format:check、build（含类型检查）通过。
- Chromium 使用拦截响应验证组合筛选、分页、草稿排除、截止排序、返回和刷新、空结果、失败重试、非法编号、403/404 和手机宽度。
- 使用隔离的 Spring Boot + H2 测试库创建演示招募，游客通过真实接口浏览、进入详情、刷新；直接访问他人的草稿正确显示未找到。未操作 MySQL。
