# 成队与队伍群交接说明

更新日期为 2026 年 11 月 20 日。本轮基于主分支 `8a43508` 开发，交付分支为 `feat/backend-team-formation`。

## 一、承接内容核验

最新主分支已具备入队申请、成员退出审核、负责人移除成员和继任退出流程，并同步更新 conversation_member 的 LEFT / REMOVED 资格。角色继续由 team_member.role 和当前负责人确定。

会话消息模块已具备私聊唯一性、会话列表、消息持久化、历史分页、afterMessageId 增量查询、消息发送幂等、未读数、已读位置、屏蔽及会话成员权限校验。原有 46 项测试在独立主分支副本中全部通过。

本轮在这些实现上接入成队事务和队伍群入口，继续复用 Controller / Service / Mapper、统一 Result、JWT 当前身份及现有 NotificationService.create(...)。

## 二、本轮完成接口

### 确认成队

```http
POST /api/recruitments/{id}/form-team
Authorization: Bearer <token>
```

仅当前负责人可以将 RECRUITING 招募确认成队，允许未满员，包括仅有负责人时确认。成功返回 HTTP 200，data 为更新后的 RecruitmentVO，status 为 TEAMED。

在同一事务中完成以下写入。

1. 锁定招募记录并检查当前负责人和状态。
2. 更新招募为 TEAMED，记录更新时间。
3. 将全部 PENDING 入队申请置为 EXPIRED，并通知对应申请人。
4. 创建该招募唯一的 ACTIVE / TEAM 会话。
5. 将当前全部 ACTIVE 正式成员加入 conversation_member，包含负责人。
6. 向所有 ACTIVE 正式成员发送成队通知。

成员未满也可确认。DRAFT、TEAMED、CLOSED 或已有队伍群的冲突状态返回 40900，其他用户返回 40300，未登录返回 40100，招募不存在返回 40400。重复和并发请求仅有一次成功，后续请求返回 409，所有写入失败均整体回滚。

### 查询队伍群

```http
GET /api/recruitments/{id}/team-conversation
Authorization: Bearer <token>
```

成功返回 HTTP 200，data 为现有 ConversationVO，前端使用其中的 id 调用消息与已读接口。仅 team_member 和 conversation_member 均为 ACTIVE 的当前队员可以查询。

招募或队伍群不存在返回 40400。有群时，非成员、已退出、已移除或群资格已失效的用户返回 40300。退出审批通过、负责人移除成员、原负责人确认继任离队后，群入口、会话列表、消息历史、发送与已读权限同步撤销。继任后的负责人继续使用同一个队伍群。

接口的字段和响应示例见 API 规范第 6.7 节，消息接口见第 8 节。[招募 API 规范](recruitment-api-spec.md)

## 三、通知与数据约束

| 通知 | 接收者 | 目标与幂等键 |
| --- | --- | --- |
| APPLICATION_EXPIRED | 成队时仍待处理的申请人 | APPLICATION，仅填 applicationId，键为 `application:{id}:expired` |
| RECRUITMENT_TEAMED | 成队时全部 ACTIVE 队伍成员 | RECRUITMENT，仅填 recruitmentId，键为 `recruitment:{id}:teamed` |

通知沿用现有创建服务和接收者、event_key 唯一约束。待处理申请不占名额，成队后新申请和申请接受操作均受 TEAMED 状态限制。

沿用现有 19 张表。conversation.recruitment_id 唯一约束保证一条招募最多一个 TEAM 群，conversation_member 的会话和用户组合主键保证成员关系唯一。会话成员保存资格、加入退出时间和已读位置，负责人角色从现有队伍数据读取。

已有数据库继续使用现有结构；从早期版本升级时使用仓库已提供的 `20261112-application-member-exit.sql`。新建开发库可执行完整初始化脚本。[数据库说明](../backend/README.md) · [ER 与事务规则](recruitment-er.md)

## 四、核验中修正的联动问题

TEAM 发送消息先按 ID 升序锁定所属及来源招募，再锁会话和群成员，更新已读先锁所属招募，与退队、移除及继任保持一致顺序，避免消息来源外键锁与成员变更相互等待。

消息的 sourceRecruitmentId 仅允许关联公开招募，来源为 DRAFT 或不存在时返回 40400，保障草稿私有性与后续删除流程。

本轮新增验证覆盖未满及满员成队、负责人权限、非 RECRUITING 状态、重复与并发成队、申请失效和两类通知、事务故障回滚，以及退出、移除和负责人继任后的群资格。

本地完整版本 Maven `verify` 共 64 项测试全部通过，失败、错误和跳过均为 0，完成可运行 JAR 打包。本轮新增 18 项，包含 10 项接口用例、5 项并发用例和 3 项故障回滚用例。额外覆盖了跨队伍公开招募来源并发，以及私有草稿来源被拒后仍可删除的回归场景。

真实 MySQL 8.0.18 运行包验证通过。三个同时确认请求返回 200 / 409 / 409，成队与接受申请争用得到一致的最终名单。未满和满员成队、待处理申请失效、两类通知、消息幂等、增量及已读均通过实际 HTTP 请求验证。

退出审批通过、成员移除和原负责人继任退出后，原成员的群入口、会话列表、历史、发送与已读访问均被撤销，继任负责人仍使用原群。群消息发送与移除竞争通过，两个群互引公开招募来源的并发发送均返回 201。草稿消息来源返回 404，随后草稿删除成功。

实际提交文件另行导出后，仓库原有 46 项测试全部通过，Maven `verify` 打包成功。64 项完整验证使用了本地新增测试及配套 H2 结构扩展。
